# QUANTLY 프로젝트 작업 기록 및 협업 규칙

이 문서는 QUANTLY 백테스팅 프로젝트의 개선 과정과 판단 근거를 이어서 기록하기 위한 문서다. 다음 작업을 시작하는 에이전트는 이 파일을 먼저 읽고, 작업이 끝난 뒤 필요한 내용을 바로 추가한다. 사용자의 별도 요청이나 확인을 기다리지 않는다.

## 프로젝트 목적

주식 초보자도 투자 전략을 이해하고 과거 시장에 적용해 볼 수 있는 랜딩페이지와 별도 백테스팅 기능창을 만든다.

## 현재 구조

- `index.html`: QUANTLY 랜딩페이지
- `backtest.html`: 백테스트 실행 화면
- `styles.css`: 기본 스타일
- `overrides.css`: 반응형·블루 테마·추가 컴포넌트 스타일
- `script.js`: 랜딩페이지 인터랙션, 스크롤 등장 애니메이션, 자산배분 주기별 차트 변경
- `backtester.js`: 종목 선택, 전략 계산, 결과 그래프, 툴팁, 최대 하락 구간 표시, 초보자 가이드 토글

## 작업 원칙

1. 사용자의 요청을 먼저 결과물로 구현하고, 불필요한 확인 질문은 줄인다.
2. 기존 기능을 깨지 않도록 변경 전 관련 파일과 현재 동작을 확인한다.
3. 랜딩페이지는 설명과 설득에 집중하고, 입력·계산 기능은 `backtest.html` 기능창에 둔다.
4. 데모 데이터와 실제 시장 데이터는 명확히 구분한다. 실제 데이터처럼 오해될 수 있는 숫자에는 안내를 붙인다.
5. 투자 관련 문구는 투자 권유로 보이지 않게 하고, 과거 성과가 미래 수익을 보장하지 않는다는 점을 표시한다.
6. 시각적 변경은 가능하면 데스크톱과 모바일을 모두 고려한다.
7. 변경 후에는 적절한 수준의 검증을 실행한다. 최소한 JavaScript 문법 검사와 주요 화면·버튼·링크 확인을 한다.
8. 비밀번호, API 키, 개인정보, 실제 계정 정보는 이 문서에 기록하지 않는다.
9. 사용자가 별도로 중단하거나 보류하라고 말하지 않는 한, 이 대화에서 `stock` 저장소의 파일을 변경한 작업은 완료 후 `git add .`, 의미 있는 커밋, `git push origin main`까지 진행한다. API 키·비밀번호·개인정보는 커밋하지 않는다.

## GitHub 자동 반영 규칙

- 원격 저장소: `https://github.com/jamjam222111/stock.git`
- 기본 브랜치: `main`
- 변경 전 `git status`로 범위를 확인한다.
- 변경 후 JavaScript 문법 검사와 가능한 범위의 로컬 확인을 먼저 실행한다.
- 검증이 끝나면 변경사항을 커밋하고 `origin/main`으로 push한다.
- push 실패 시 로컬 커밋 상태와 실패 원인을 사용자에게 알리고, 인증·충돌·네트워크 문제를 임의로 우회하지 않는다.

### 2026-11-07 — 데모 주가 데이터 초기화 스크립트 추가
